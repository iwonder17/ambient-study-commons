{backend process}: {
-user will have multiple sessions per day the end of the days like 20:00, the backend send journal sessoins of that days to a AI api and adding with details in canvas data to make more correct data in journal part 
+ to make a master version journal of that days and save down, replacing multiple sessions during thay day. 
+ using a skillCheck promp to extract the user skills: strong, weekness, roles in a team, expreience user have, mindset, thinking partern , characer analysis and save, update a userSkill.txt in database
+ using a dreamCheck promp to extract what user want, dream, mentions or topic they are working on during that day+ the data in database itself userDream.txt to compare: if the ai found todays dream\topic is simmlar with the pass, it rise a number count by 1 and save 20 latest time stamp where user mention about that. For example: setup minecraft server:mentioned 30: {date, date, date, date, date...}. this files use to compare this user dream, topoic iwth others who shared simliar to bring them together to discuss, connect, slove, archive the shared goal together.
- Canvas data is stored separately brand or folder for each user: based on user permissions, the extension scrapes authorized items (modules, grades, calendar events, syllabi) and send to backend server to save each into its dedicated file (e.g., `canvasModule.txt`, `canvasGrades.txt`, etc.); also from those the server use AI to analyze to make a files named: canvas this file will keep track of upcoming assignment/ exam dat, and remind user via notification, email, or on the dashboard.:

   data objects:
   --------------------------------------------------
   MasterJournal {
     id: string (UUID)
     userId: string (FK -> UserAccount.id)
     date: date (YYYY-MM-DD, one per day per user)
     content: string (AI-generated master journal text for that day)
     highlights: string (notable moments extracted by AI)
     improvements: string (areas to improve extracted by AI)
     sessionCount: integer (how many raw sessions were merged)
     createdAt: timestamp
     updatedAt: timestamp
   }

   UserSkill {
     userId: string (FK -> UserAccount.id)
     strengths: string[] (list of identified strengths)
     weaknesses: string[] (list of growth areas)
     teamRoles: string[] (e.g., "leader", "researcher", "debugger", "designer")
     experience: string[] (e.g., "Python", "web scraping", "game dev")
     mindset: string (AI summary of thinking patterns and mindset)
     characterAnalysis: string (AI personality/work-style summary)
     updatedAt: timestamp
   }

   UserDream {
     id: string (UUID)
     userId: string (FK -> UserAccount.id)
     topic: string (the dream/project/idea name, e.g., "Setup Minecraft server")
     mentionCount: integer (how many times this topic appeared, incremented on match)
     recentTimestamps: timestamp[] (last 20 dates where user mentioned this topic)
     firstMentioned: timestamp
     lastMentioned: timestamp
     status: enum ("tracking", "submitted_to_pool", "matched")
   }

   CanvasData {
     id: string (UUID)
     userId: string (FK -> UserAccount.id)
     dataType: enum ("modules", "grades", "syllabi", "events")
     content: JSON (the scraped data, structured per type)
     scrapedAt: timestamp
   }

   CanvasReminder {
     id: string (UUID)
     userId: string (FK -> UserAccount.id)
     title: string (e.g., "CS101 Midterm Exam")
     type: enum ("assignment", "exam", "event")
     dueDate: timestamp
     courseName: string
     isNotified: boolean (has the user been alerted yet)
     createdAt: timestamp
   }
   --------------------------------------------------

   scheduled jobs:
   --------------------------------------------------
   dailyPipeline {
     trigger: cron job at 20:00 user local time (or configurable)
     for each active user:
       1. fetch all SessionRecord where date = today
       2. fetch CanvasData if available
       3. call AI API with journalPrompt (sessions + canvas context) -> save MasterJournal
       4. call AI API with skillCheckPrompt (sessions) -> upsert UserSkill
       5. call AI API with dreamCheckPrompt (sessions + existing UserDream list) -> upsert UserDream entries
       6. optionally archive/delete raw SessionRecords for that day
   }

   weeklyReviewTrigger {
     trigger: cron based on user's reviewCycleDays setting (default every 7 days)
     action: sets a flag weeklyReviewAvailable = true for that user
     the extension polls or receives push for this flag to show the Weekly Review button
   }

   canvasReminderCheck {
     trigger: daily at 08:00 (morning)
     for each user with canvas data:
       check CanvasReminder entries where dueDate is within next 48 hours and isNotified = false
       send notification (email, extension badge, or dashboard alert)
       mark isNotified = true
   }
   --------------------------------------------------

   API endpoints:
   --------------------------------------------------
   POST   /api/auth/google           -> Google OAuth login, returns token + user
   GET    /api/me                    -> get current user profile
   PUT    /api/me/preferences        -> update UserPreferences (toggles, review cycle)
   PUT    /api/me/freetime           -> update FreeTimeSlot entries

   POST   /api/sessions              -> save a new SessionRecord
   GET    /api/sessions?date=        -> get sessions for a date
   GET    /api/sessions?week=        -> get sessions for a week

   GET    /api/journals?page=&limit= -> get MasterJournal list (paginated, 20 default)
   GET    /api/journals/:date        -> get single day's master journal

   GET    /api/skills                -> get current user's UserSkill
   GET    /api/dreams?page=&limit=   -> get user's UserDream list (paginated)

   POST   /api/canvas/:type          -> save scraped Canvas data (type = modules|grades|syllabi|events)
   GET    /api/canvas/reminders      -> get upcoming CanvasReminder items

   GET    /api/weekly-review/status  -> check if weekly review is available
   GET    /api/weekly-review/bundle  -> get the bundled journals + prompt for clipboard

   POST   /api/dreams/:id/submit     -> submit a dream topic to the public matching pool
   GET    /api/invitations?page=     -> get pending match invitations (paginated)
   POST   /api/invitations/:id/respond  -> accept or decline an invitation { action: "accept"|"decline" }

   GET    /api/credit-score          -> get user's private credit score

   GET    /api/greeting-room/:meetingId  -> get greeting room info + WebSocket URL
   POST   /api/greeting-room/:meetingId/join -> join the greeting room

   POST   /api/data/export           -> generate full data export (returns download link)
   DELETE /api/data/partial           -> delete selected data { type, ids }
   DELETE /api/data/wipe              -> wipe ALL user data (requires confirmation token)
   --------------------------------------------------
}

{attendance, confirmation & credit score}: {
How the system ensures users show up on time and respect agreed meetings:

1. 5-Hour Advance Confirmation:
   - Exactly 5 hours before the scheduled greeting meeting, the backend sends a confirmation letter/email to both users.

2. Personal Credit Score (Private to User):
   - Privacy: The credit score is strictly private and visible ONLY to the user on their own dashboard.
   - Point Deductions: -1 point per missed meeting.
   - Priority & Matching Impact: lower score = fewer invitations.

   data objects:
   --------------------------------------------------
   CreditScore {
     userId: string (FK -> UserAccount.id)
     score: integer (default starting value, e.g., 50 or 100)
     totalMeetingsScheduled: integer
     totalMeetingsAttended: integer
     totalNoShows: integer
     history: CreditEvent[] (log of score changes)
   }

   CreditEvent {
     id: string (UUID)
     userId: string
     meetingId: string (FK -> Meeting.id)
     eventType: enum ("attended", "no_show", "bonus")
     pointChange: integer (e.g., -1 for no_show, +1 for bonus)
     newScore: integer (score after this event)
     createdAt: timestamp
